# Karaoke Player 곡별 조정키 저장 스펙

- 작성일: 2026-09-15
- 연관 스펙: `003-player-layout.md`
- 대상: 003 §4.3 키 패널의 조정 값 저장

이 문서는 003 키 패널의 곡별 조정 반음 수 자동 저장과 복원을 다룬다.

## 1. 목표와 비목표

```text
키를 조정한 곡을 다시 불러오거나 앱을 재시작하면 마지막 조정키로 재생된다.
```

| 영역      | 목표                                                 |
| --------- | ---------------------------------------------------- |
| 저장·복원 | 버튼·단축키 조정 값을 곡별 저장하고 화면·엔진에 복원 |

| 비목표              | 이유                                     |
| ------------------- | ---------------------------------------- |
| 원키 변경·음원 변환 | 요청은 재생 조정 값 저장이며 원본은 유지 |

## 2. 성공 기준

1. −6–+6 정수를 곡별 저장하며 DB 재개방 후 유지한다. 기존·새 곡 기본값은 0이다.
2. 곡 재로드는 저장 완료 후 최신 값을 읽고 화면·엔진에 적용한다.
3. 연속 변경은 입력 순서대로 저장한다. 이전 곡이나 로드 해제 후 늦은 조회 결과는 무시한다.
4. 로드 중·곡 없음·비정상 입력은 저장하지 않는다. 저장 실패는 현재 재생 값을 유지하고 오류 센터에 알린다.
5. 원키 리셋은 0을 저장한다. 원키 메타와 기존 볼륨 저장은 유지한다.

## 3. 전제 조건

- `playerStore.ts`의 `setPitch`는 키 패널·단축키 공통 진입점이다.
- `LibraryStore.ts`는 SQLite v7과 곡별 볼륨 저장을 제공한다.
- preload API 타입은 `src/preload/index.ts`에서 추론한다.

## 4. 기능 범위

### 4.1 저장·복원

SQLite v8에 `pitch_semitones INTEGER NOT NULL DEFAULT 0`을 추가한다. 전용 IPC로 조회·저장하며 Main에서 정수·범위를 검증한다. 조정은 즉시 적용하고 곡별 저장을 직렬화한다. 로드 시 저장을 기다린 뒤 revision을 확인하고 복원한다. 볼륨 저장은 독립적으로 유지한다.

### 4.2 구현 슬라이스

| 슬라이스 | 산출물             | 소유(수정 가능) 경로                                                | 수정 금지 경로          | 선행 조건 | 상태    |
| -------- | ------------------ | ------------------------------------------------------------------- | ----------------------- | --------- | ------- |
| P1       | DB·IPC·복원·테스트 | LibraryStore, ipc, preload, shared/types, playerStore와 관련 테스트 | 오디오 워클릿·음원 처리 | 없음      | 완료 |

P1은 기준 1–5 자동 검증으로 완료한다. 직접 순차 구현한다. 완료 슬라이스는 재작업하지 않는다. 종료 전 §5 검증과 exit code를 보고하며 훅 우회·임의 commit/stage는 하지 않는다.
