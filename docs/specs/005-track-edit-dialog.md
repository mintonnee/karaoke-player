# Karaoke Player 곡 수정 팝업 스펙

- 작성일: 2026-09-14
- 연관 스펙: `000-karaoke-app-spec-draft.md`, `002-bpm-key-analysis.md`, `004-import-dialog.md`
- 대상: 000 §5 S3.2 — 곡 메타 편집을 팝업으로 전환하고 앨범 커버 변경을 추가한다.
- 상태: 구현 완료 (자동 검증 통과, UI·재시작 수동 확인 대기)

이 문서는 `000-karaoke-app-spec-draft.md`의 S3.2에서 곡 정보와 앨범 커버를 함께 수정하는 범위를 다룬다. 음원 교체와 가사 편집은 다루지 않는다.

## 1. 목표와 비목표

```text
사용자는 곡 수정 팝업에서 곡 정보와 앨범 커버를 미리 확인하고 저장하여 목록과 현재 곡 표시에 반영하며, 앱을 다시 실행해도 수정 결과를 확인할 수 있다.
```

| 영역        | 목표                                                                        |
| ----------- | --------------------------------------------------------------------------- |
| 진입과 구성 | 기존 행의 편집 버튼으로 앱 내부 팝업을 열고 커버와 곡 정보를 함께 표시한다. |
| 곡 정보     | 기존 제목·아티스트·앨범·BPM·키 편집을 유지한다.                             |

| 저장        | 저장 전에는 원본을 유지하고 성공 시 메타데이터와 커버를 함께 반영한다.      |
| 재생        | 현재 재생을 이어가면서 표시 정보만 갱신한다.                                |

| 다중 곡 일괄 편집                        | 단일 곡 팝업의 입력·저장 단위를 유지한다.                                                        |

## 2. 성공 기준

1. 목록 행의 편집 버튼을 누르면 `곡 수정` 팝업 하나가 열리고 해당 곡의 현재 커버와 제목·아티스트·앨범·BPM·키가 채워진다. 행 높이·순서와 현재 재생 곡은 바뀌지 않는다.
2. 제목이 공백뿐이면 저장할 수 없다. 아티스트·앨범·BPM·키는 비울 수 있다. 잘못된 BPM·키는 필드 근처에 사유를 표시하고 Main에서도 거부한다.
3. JPG/JPEG·PNG·WebP 이미지 한 개를 선택하거나 커버 영역에 드롭하면 저장 전 미리보기가 바뀐다. 선택창 취소는 기존 초안을 유지한다. 여러 파일·미지원 형식·손상 이미지·크기 제한 초과는 오류를 표시하고 직전 유효한 초안을 유지한다.
4. `커버 제거`를 누르면 기본 음표 이미지가 미리 보인다. `변경 취소`를 누르면 팝업을 열 때의 커버로 돌아간다. 저장하지 않고 팝업을 닫으면 커버 파일과 곡 정보가 바뀌지 않는다.
5. 저장 성공 후 팝업이 닫히고 목록과 현재 곡 표시에 새 정보·커버가 나타난다. 커버만 연속 변경해도 캐시 때문에 이전 이미지가 남지 않는다. 원본 이미지 파일을 이동하고 앱을 재시작해도 저장한 커버가 보인다.
6. 커버 제거를 저장하면 재시작 후에도 기본 이미지가 보이며 자동 커버 추출이 제거한 커버를 복원하지 않는다. 이미 실행 중인 추출 결과도 사용자가 저장한 교체·제거 결과를 덮지 않는다.
7. 저장 처리 중 중복 저장·입력 변경·닫기는 차단된다. 파일 읽기·복사·DB 저장 실패 시 팝업과 입력이 유지되고 오류·재시도가 제공되며 기존 정보와 커버를 모두 보존한다. 저장 도중 종료 후 재시작해도 이전 또는 새 결과의 일관된 한 세트만 노출한다.
8. 팝업이 열린 동안 Tab/Shift+Tab 포커스가 내부에 머물고 배경 조작과 재생 단축키가 차단된다. 저장 중이 아닐 때 Escape·닫기·취소는 초안을 버리고 원래 편집 버튼으로 포커스를 돌린다. 버튼이 검색 결과에서 사라졌으면 목록의 안정적인 포커스 지점으로 돌아간다.
9. 재생 중인 곡을 저장해도 재생 위치·재생/일시정지 상태·루프·키 이동·믹서 값이 유지되고 음원을 다시 로드하지 않는다. 제목 또는 커버만 수정하면 BPM·키·분석 출처·신뢰도가 유지된다.
10. 저장 후 현재 검색어에 맞는 목록이 표시된다. 제목·아티스트·앨범 변경 시 검색 키 갱신을 요청하되 오래된 비동기 결과가 최신 메타의 검색 키를 덮지 않는다. 커버만 변경하면 검색 키 생성·가사 조회·오디오 분석·스템 분리를 새로 시작하지 않는다.
11. 팝업 도중 들어오는 상태·분석 갱신은 사용자가 편집한 입력을 덮지 않는다. 저장은 변경 필드만 적용하여 최신 비편집 필드를 유지한다. 대상 곡이 삭제되었으면 저장을 거부하고 곡이나 디렉토리를 재생성하지 않는다.

## 4. 기능 범위

### 4.1 진입점과 팝업 구성

- 기존 행의 편집 버튼을 유지하고 인라인 폼을 앱 내부 모달로 교체한다. 편집 버튼 클릭은 행의 곡 로드를 유발하지 않는다.
- 상단에는 `곡 수정`과 닫기 버튼, 본문에는 커버 영역과 곡 정보 영역, 하단에는 `취소`와 `저장`을 배치한다. 가져오기 팝업의 색상·간격·버튼 스타일을 따른다.
- 넓은 창에서는 왼쪽에 정사각형 커버 미리보기, 오른쪽에 입력을 배치한다. 좁은 창에서는 커버·곡 정보 순으로 쌓고 본문을 스크롤하여 하단 버튼이 창 밖으로 잘리지 않게 한다.
- 커버 영역에는 `이미지 선택`(커버가 있으면 `이미지 변경`), `커버 제거`, 초안 변경 시 `변경 취소`를 제공한다. `변경 취소`는 커버 초안만 되돌린다. 커버가 없는 초안에서는 제거 버튼을 비활성화한다.
- 입력은 제목(필수), 아티스트, 앨범, BPM, 원키 순으로 배치한다. BPM·원키는 같은 줄에 배치할 수 있다. 원키는 재생 중 키 이동과 다른 값임을 보조 문구로 설명한다.
- 필드에는 실제 label을 제공하고 모달 제목과 접근성 이름을 연결한다. 최초 포커스는 제목 입력이다. 배경 클릭으로 닫지 않는다. 수정·가져오기·설정 팝업이 중첩되지 않게 한다.
- 모든 기존 곡 상태에서 편집 진입을 유지한다. 비동기 상태 갱신으로 목록 행이 바뀌거나 검색에서 빠져도 팝업은 대상 ID와 초안을 유지한다.

### 4.2 입력과 이미지 초안

- 제목·아티스트·앨범은 앞뒤 공백을 제거한다. 빈 제목은 오류, 빈 선택 필드는 `null`이다. BPM·키 규칙은 002 §4.2와 현재 공유 상수를 따른다.
- 팝업을 연 시점의 값과 비교해 변경 필드를 구분한다. BPM·키를 수정하지 않았다면 저장 요청에서 생략한다. 변경 없음이면 저장 버튼을 비활성화한다.
- 커버 초안은 `유지`, `교체`, `제거`를 구분한다. 이미지 선택과 미리보기는 저장된 `cover.jpg`를 쓰지 않는다.
- 지원 형식과 파일 바이트 상한은 가져오기의 `ALLOWED_COVER_EXT`, `MAX_COVER_BYTES`와 동일하게 적용한다. Main은 일반 파일 여부·확장자·크기·실제 디코딩 가능 여부를 미리보기와 저장 시 모두 검사한다. 확장자만 바꾼 손상 파일을 허용하지 않는다.
- 미리보기는 이미지 비율을 유지하여 전체 이미지가 보이게 한다. 빠르게 이미지를 연속 선택하면 마지막 선택 결과만 표시하고 이전 미리보기 응답은 무시한다.
- 이미지 드롭은 커버 영역에서만 처리하고 배경 가져오기·행 정렬 이벤트로 전파하지 않는다. 팝업 바깥 파일 드롭도 가져오기를 실행하지 않는다.

### 4.3 저장 계약과 파일 일관성

- 곡 수정은 Main의 단일 저장 작업으로 메타 변경분과 커버 동작을 받는다. 기존 `TrackMetaInput` 호출자의 계약을 깨지 않도록 전용 요청 타입을 추가하거나 호환 확장한다. 채널 이름과 내부 함수 구성은 구현 시 결정한다.
- Main은 대상 ID가 실제 DB 곡인지 확인하고 수정 가능한 필드와 커버 동작을 검증한다. 상태·음원 경로·분석 신뢰도 등 임의 필드를 입력으로 갱신하지 않는다. 대상 커버 경로는 Main이 곡 ID로 결정한다.
- 변경된 메타 필드만 최신 행에 합친다. BPM·키 중 하나를 직접 수정하면 002의 기존 사용자 분석값 계약을 따르고 생략한 다른 값은 최신 값을 유지한다.
- 교체 이미지는 앱 관리 디렉토리에 복사하여 기존 `cover.jpg` 표시 계약을 유지한다. 선택 원본을 이동·삭제·덮어쓰지 않는다. 저장 중 다시 읽은 파일이 유효하지 않으면 전체 저장을 실패시킨다.
- 메타와 커버를 별도 IPC로 순차 저장하지 않는다. 임시 파일·기존 커버 백업·복구 기록 등으로 실패 시 이전 상태를 복구하고, 시작 시 미완료 작업을 복구한 뒤 라이브러리를 노출한다. DB 트랜잭션만으로 파일 교체가 원자적이라고 가정하지 않는다.
- 커버 제거는 `cover.jpg`를 제거하고 `cover.none`을 남긴다. 교체는 새 커버를 설치하고 불필요한 `cover.none`을 정리한다. 이는 명시적인 제거 저장에만 적용하며 팝업 초안 조작으로 수행하지 않는다.
- 같은 곡의 저장·삭제·커버 자동 추출을 조정하여 오래된 추출 결과가 사용자 저장을 덮지 않게 한다. 큐 대기뿐 아니라 이미 실행 중인 추출도 다룬다. 구체적인 직렬화·세대 검사·복구 기록 형식은 성공 기준이 우선, 구현 방식은 자유다.
- 완료 시 최종 `Track`과 갱신 이벤트를 제공한다. 커버만 바뀌어도 캐시 식별자가 바뀌어야 하며 같은 시각 값 충돌도 고려한다. 성공 알림은 DB와 파일이 모두 확정된 뒤 보낸다.

### 4.4 저장 이후와 오류

- 현재 곡 정보와 목록만 갱신하며 `loadTrack`을 호출하지 않는다. 오디오·가사 파일·루프·믹서 상태는 수정 저장의 대상이 아니다.
- 현재 검색어를 유지하고 저장 후 필터를 재평가한다. 메타 변경으로 검색 키를 다시 만들 때 최신 메타인지 확인한 뒤 반영하고 목록도 갱신한다. 검색 키 생성 실패는 이미 완료한 저장을 되돌리지 않는다.
- 저장 실패는 팝업에 원인과 재시도 가능한 상태를 표시한다. 같은 오류를 오류 센터에 중복 표시하지 않는다. 대상 곡이 사라진 오류는 재저장을 비활성화하고 닫기를 제공한다.
- 취소·닫기·Escape는 저장 전 초안을 버린다. 별도의 변경 폐기 확인창은 두지 않고 가져오기 팝업과 같은 닫기 규칙을 따른다.

### 4.5 구현 슬라이스

아래 경계는 후속 구현용이며 이번 스펙 작성에서 실행하지 않는다. 새 파일 경로는 예정 산출물이다.

| 슬라이스 | 산출물                                                                | 소유(수정 가능) 경로                                                                                                                                                              | 수정 금지 경로                     | 선행 조건                                       | 상태 |
| -------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | ----------------------------------------------- | ---- |
| E1       | 저장 계약, 이미지 검증, 파일·DB 복구, 추출·검색 키 경합 방지와 테스트 | `src/shared/types.ts`, `src/shared/trackEdit.ts`, `src/shared/__tests__/trackEdit.test.ts`, `src/main/**`, `src/preload/**`                                                       | `src/renderer/**`, 루트 설정, 문서 | 없음                                            | 완료 |
| E2       | 수정 팝업, 커버 초안, 접근성, 행 진입·검색·현재 곡 표시 연결과 테스트 | `src/renderer/**`                                                                                                                                                                 | E1 소유 경로, 루트 설정, 문서      | E1 계약 확정 후 착수, E1 검증 통과 후 통합 확인 | 완료 |
| E3       | 통합 검증, 문서 상태 갱신, 필요한 공용 설정 조정                      | `docs/specs/005-track-edit-dialog.md`, `docs/specs/README.md`, `docs/draft/000-karaoke-app-spec-draft.md`, `package.json`, `pnpm-lock.yaml`, `vitest.config.ts`, `tsconfig*.json` | E1·E2 소유 경로                    | E1·E2 완료                                      | 완료 |

- 완료 판정: E1은 기준 2–7·9–11의 Main 저장·이벤트 계약, E2는 기준 1–5·7–11의 UI 동작, E3는 기준 1–11 전체의 통합 검증이다. UI 기준은 수동 검증까지 완료해야 완료로 표시한다.
- 각 슬라이스는 소유 경로만 수정한다. 공용 설정은 E3만 소유하며 필요하면 감독자가 선행 설정 작업의 순서를 조정한다. 그 밖의 경로가 필요하면 구현 전에 소유 경계를 갱신한다.
- 완료된 슬라이스는 재작업하지 않는다. 결함이 발견되면 감독자가 해당 슬라이스를 명시적으로 다시 열어 상태를 갱신한다.
- 실제 슬라이스 실행에는 `orchestrate-slices` 스킬을 사용한다. 각 에이전트는 종료 전 §5의 해당 검증 명령을 실행하고 exit code를 보고한다.
- 훅 우회(`--no-verify`, `LEFTHOOK=0`)는 금지한다. git 상태 변경(commit/stage)은 감독자 또는 사용자만 수행하며, 이 저장소에서는 사용자 명시 요청 없이 수행하지 않는다.

## 5. 검증 방법

다음은 구현 완료 후 실행할 명령이다. 현재 테스트의 통과만으로 신규 기능을 검증했다고 간주하지 않는다.

```bash
# 기준 2–7·9–11: E1/E2에서 입력·초안·저장 실패·복구·경합·이벤트 테스트를 추가한 후 실행
pnpm test

# 기준 1–11의 타입·IPC 계약 및 정적 회귀 검사 (화면 동작은 아래 수동 확인 필요)
pnpm typecheck
pnpm lint

# 기준 1·5·8·9의 수동 통합 확인을 위한 빌드 및 실행
pnpm build
pnpm start
```

- 기준 1·2·8: 다른 곡 재생 중 편집을 열고 기존 값, 필드 검증, 키보드 포커스 순환, 단축키 차단, Escape·취소·배경 클릭, 좁은 창 스크롤을 확인한다.
- 기준 3·4: 각 지원 이미지, 커버 없는 곡, 손상 이미지, 상한 초과 파일, 복수 드롭, 선택창 취소, 빠른 연속 선택을 확인한다. 미리보기 후 취소했을 때 파일과 DB가 그대로인지 확인한다.
- 기준 5·6: 교체 두 번과 제거 저장을 각각 수행한다. 선택 원본을 이동한 뒤 앱을 재시작하고 결과가 유지되는지 확인한다. 자동 추출 완료를 지연시킨 테스트로 교체·제거 결과가 덮이지 않는지 검증한다.
- 기준 7: 임시 테스트 디렉토리와 DB에서 파일 설치 실패·DB 실패·파일 교체와 DB 확정 사이의 종료를 주입한다. 재시작 복구 후 메타와 이미지가 일관되고 임시 산출물이 정리되며 실패 전에 있던 커버를 잃지 않는지 확인한다. 실제 사용자 라이브러리에서 장애를 주입하지 않는다.
- 기준 9: 자동 분석된 재생 곡에서 커버만 수정한 뒤 분석 컬럼 보존과 오디오 재로드 0회를 검사하고 재생 위치·루프·키 이동·믹서를 확인한다. 원키 직접 수정은 사용자 분석값으로 저장되는지도 확인한다.
- 기준 10·11: 검색 중 제목을 바꿔 필터 반영을 확인한다. 상태·분석 이벤트, 순서가 뒤집힌 검색 키 응답, 대상 삭제를 주입하여 초안과 최신 비편집 필드 보존·오래된 결과 폐기·삭제 곡 재생성 방지를 확인한다.
