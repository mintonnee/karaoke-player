# Karaoke Player 곡 수정 키·BPM 재측정 스펙

- 작성일: 2026-09-17
- 연관 스펙: `005-track-edit-dialog.md`, `002-bpm-key-analysis.md`, `000-karaoke-app-spec-draft.md`
- 대상: 005 §4.2 곡 정보 초안과 002의 BPM·키 분석을 연결하는 명시적 재측정
- 상태: 구현 완료 (자동 검증 통과, 실제 앱 수동 확인 대기)

이 문서는 `005-track-edit-dialog.md`의 곡 수정 창에서 BPM과 원키를 재측정하고 결과를 초안에 적용하는 범위를 다룬다. 분석 알고리즘 개선과 음원 재분리는 다루지 않는다.

## 1. 목표와 비목표

```text
곡 수정 창에서 BPM 또는 원키 재측정을 누르면 해당 입력에 추정값이 표시되고, 저장하면 반영되며 취소하면 기존 값이 유지된다.
```

| 영역   | 목표                                                                           |
| ------ | ------------------------------------------------------------------------------ |
| 진입점 | BPM 옆 `BPM 재측정`, 원키 옆 `원키 재측정` 버튼을 제공한다.                    |
| 분석   | 기존 반주 `inst.wav`와 분석 엔진을 사용해 수동 입력 이력이 있는 곡도 측정한다. |
| 초안   | 요청한 필드만 갱신하고 제목·아티스트·커버·다른 분석 필드의 초안을 보존한다.    |
| 확정   | 기존 곡 수정 저장 계약으로 확정하고 재생을 이어간다.                           |

| 비목표                          | 제외 이유                                                                                      |
| ------------------------------- | ---------------------------------------------------------------------------------------------- |
| 분석 정확도 개선·새 모델 도입   | 이번 요청은 기존 측정 기능의 수동 진입점이며 동일 음원·모델의 결과가 달라짐을 보장하지 않는다. |
| 재분리·원본 음원 대체 분석      | 준비된 반주를 다시 분석하는 범위이며 처리 파이프라인을 재시작할 필요가 없다.                   |
| 전체 라이브러리 일괄 재측정     | 단일 곡 수정 창에 대한 요청이다.                                                               |
| 필드별 분석 출처·신뢰도 DB 확장 | 기존 사용자 확정값 저장 계약을 재사용하므로 스키마 변경이 필요하지 않다.                       |

## 2. 성공 기준

1. 곡 수정 창의 BPM·원키에 각각 재측정 버튼이 보인다. `ready`가 아닌 곡 또는 런타임 준비 전에는 비활성화되고 이유가 표시된다. Main도 실행 조건을 검증한다.
2. 수동 입력값이 있는 `ready` 곡에서 재측정하면 기존 `inst.wav`를 분석한다. BPM 요청은 BPM만, 원키 요청은 원키만 바꾸며 다른 필드와 커버 초안을 보존한다.
3. 요청 중 작업 대기/분석 중임을 알 수 있는 상태 문구를 표시하고 중복 요청과 저장을 차단한다. 기존 분리·분석 큐와 함께 실행해 사이드카 작업이 겹치지 않는다.
4. 성공·실패·창 닫기 모두에서 재측정 요청 자체는 DB·커버·음원·곡 상태를 변경하거나 `trackUpdated`를 발생시키지 않는다. 별도로 진행되는 자동 분석의 기존 동작은 유지한다.
5. 유효한 결과를 적용한 뒤 저장하면 변경 필드만 기존 저장 경로로 확정한다. 해당 값이 바뀌면 `analysis_source='user'`, 양쪽 신뢰도 `NULL`이라는 기존 계약을 따르고 자동 백필이 덮어쓰지 않는다. 저장 전 취소하면 재측정 초안은 폐기된다.
6. 요청한 값이 `null`이거나 유효하지 않으면 기존 입력을 보존하고 해당 필드를 추정하지 못했다는 메시지를 표시한다. 미요청 필드의 실패 때문에 유효한 요청 필드 결과를 버리지 않는다. 신뢰도가 낮은 유효한 값은 불확실함을 표시하며 사용자가 검토 후 저장할 수 있다.
7. 반주 누락, 런타임 미준비, 분석 실패·타임아웃에서 입력을 유지하고 팝업 안에 오류를 표시한다. 재시도가 가능하며 동일 오류를 알림 센터에 중복 기록하지 않는다. 분석 실행 타임아웃은 기존 120초를 유지한다.
8. 대기·분석 중 취소·닫기·Escape가 가능하다. 닫은 창의 응답은 무시하고 다른 곡이나 다시 연 창에 적용하지 않는다. 요청 중 두 분석 입력은 잠그되 제목·아티스트·커버 편집은 유지한다.
9. 대기 중 또는 실행 중 대상이 삭제되거나 `ready` 조건을 잃으면 결과를 적용하지 않는다. 삭제된 곡·디렉토리를 재생성하지 않는다. 같은 곡의 요청이 이미 대기·실행 중이면 Main은 추가 실행을 거부하고 명확한 사유를 돌려준다.
10. 저장 후 현재 곡 표시는 갱신되지만 재생 위치·재생 상태·루프·조정키·믹서 값은 유지되고 오디오를 다시 로드하지 않는다. 분석값이 원래와 같고 다른 수정이 없으면 저장은 계속 비활성화된다.
11. 버튼은 키보드로 실행할 수 있고 상태 문구는 보조 기술에 전달된다. 기존 모달 포커스 순환·배경 단축키 차단·좁은 창 스크롤이 유지된다.

## 4. 기능 범위

### 4.1 버튼과 결과 적용

- 버튼의 대상은 BPM 또는 원키다. 안내 문구는 `반주에서 다시 추정합니다. 저장해야 반영됩니다.`로 한다.
- 요청 시 선택 필드에 이미 편집한 초안이 있어도 성공하면 그 필드를 교체한다. 버튼 실행이 해당 값의 재측정 의사 표현이므로 추가 확인창은 두지 않는다.
- 기존 워커가 두 값을 함께 계산하더라도 선택 필드만 적용한다. 별도 워커 명령·모델·의존성을 추가하지 않는다. 요청마다 새 분석을 실행하고 이전 결과 캐시로 대신하지 않는다.
- 결과 정규화·범위 검사는 기존 BPM·키 계약을 따른다. 유효성 판단은 Main에서 수행한다. 낮은 신뢰도 표시 기준은 002 및 `src/shared/analysisFormat.ts`를 따른다.
- 측정 출처·신뢰도 안내는 초안용이다. 사용자가 측정값을 다시 편집하면 그 안내를 해제한다. 저장된 출처는 §4.3을 따른다.

### 4.2 Main·IPC와 비동기 수명

- 전용 미리보기 분석 요청에 곡 ID와 대상(`bpm` 또는 `key`)을 전달한다. 성공 응답은 검증한 해당 값·신뢰도를, 실패는 구분 가능한 사유를 제공한다. 채널명·타입명은 구현 시 확정한다.
- Main은 ID·대상·런타임·곡 상태를 검증하고 DB에 존재하는 곡의 관리 경로에서 반주를 찾는다. 렌더러가 전달한 임의 파일 경로는 받지 않는다. 큐 실행 직전과 완료 후에도 대상 존재·상태를 확인한다.
- 자동 분석의 `refresh`를 그대로 호출하지 않는다. 저장 없이 측정 결과를 반환하는 경로를 추가하고 워커 실행 부분을 필요한 만큼 공유한다. 기존 자동 분석과 `analysis_source='user'` 보호 조건은 보존한다.
- 기존 `JobQueue`에 결과를 기다릴 수 있는 작업을 등록한다. 큐 대기에는 워커 실행 제한 120초를 소비하지 않는다. 정밀 진행률·큐 순번은 필요하지 않으며 `대기 또는 분석 중…`이라는 하나의 상태 문구도 허용한다.
- 같은 곡의 수동 요청은 대기·실행을 합쳐 하나만 허용한다. 성공·실패 모두에서 점유 상태를 해제한다. 창을 닫고 다시 요청했을 때 기존 요청이 남아 있으면 진행 중임을 알려준다.
- 창을 닫으면 결과 적용 권한을 폐기한다. 이번 범위에서 사이드카 강제 중단·전역 큐 취소는 추가하지 않는다. 이미 접수한 작업은 종료까지 실행할 수 있으나 결과는 저장하지 않는다.
- 렌더러는 창 인스턴스·요청 세대로 늦은 응답을 무시한다. 기존 자동 `trackUpdated` 이벤트가 편집 초안을 덮지 않게 한다.
- 오류 응답은 팝업에서 처리한다. 수동 경로는 자동 분석용 오류 알림을 별도로 발생시키지 않는다.

### 4.3 저장과 재생

- 재측정은 입력 보조 기능이다. 005의 변경 필드 패치·커버 원자 저장·삭제 검사·재생 보존 계약을 재사용한다.
- 저장 시 변경된 분석값을 사용자가 확인한 값으로 취급한다. 두 필드에 하나의 출처를 사용하는 현재 스키마에 맞춰 `user`로 저장하며, 신뢰도는 기존 수동 저장과 같이 양쪽 모두 비운다. 재측정 결과를 자동 출처로 직접 저장하는 경로는 추가하지 않는다.
- 값이 원래와 같으면 해당 필드를 패치에 포함하지 않는다. 제목·커버만 변경한 경우 분석 출처·신뢰도를 보존한다.
- 자동 분석 이벤트가 발생하더라도 수정 시작 기준과 편집 초안의 비교가 흔들리지 않도록 기존 변경 감지 동작을 검증한다.

## 5. 검증 방법

다음은 구현 후 실행할 검증이다. 스펙 작성만으로 기능이 검증된 것으로 표시하지 않는다.

```bash
# 기준 1–10: 신규 서비스·IPC·초안 회귀 테스트를 포함해 실행
pnpm test

# 기준 1–11: 공유 계약·컴포넌트 정적 검사 (UI 동작 증명은 별도)
pnpm typecheck
pnpm lint

# 기준 1–11: 수동 통합 검증용 앱 빌드·실행
pnpm build
pnpm start
```

- 기준 2·4–7: 임시 DB·트랙 디렉토리와 가짜 워커로 정상·부분 결과·낮은 신뢰도·잘못된 결과·실패·타임아웃을 주입한다. 미리보기 전후 DB 분석 컬럼·상태·메타·파일이 같고 갱신 이벤트가 없는지 확인한다. 저장한 뒤에만 기존 사용자 값 계약으로 바뀌는지 검사한다.
- 기준 1·3·8·9: 제어 가능한 지연 작업으로 큐 대기, 중복 요청, 실행 직전 삭제, 실행 중 삭제, 상태 변경, 닫기·재열기를 재현한다. 동시 워커 실행 1개, 대기 종료 후 요청 점유 해제, 늦은 응답 미반영을 검사한다.
- 기준 2·5·8·10: 제목·커버·다른 분석 필드를 먼저 편집한 후 한 필드만 측정한다. 성공·실패·저장·취소·동일 값 반환에서 미요청 초안과 저장 패치가 유지되는지 검사한다. 별도 자동 분석 이벤트도 주입한다.
- 기준 1–3·6–8·11: 실제 앱에서 각 버튼, 준비 전 비활성 사유, 상태 문구, 오류 후 재시도, Tab/Shift+Tab·Escape, 작은 창 레이아웃을 확인한다.
- 기준 5·10: 재생 중 재측정한 값을 저장하고 목록·현재 곡 표시와 재시작 후 값 보존을 확인한다. 오디오 재로드 없이 위치·루프·조정키·믹서가 유지되는지 확인한다.
