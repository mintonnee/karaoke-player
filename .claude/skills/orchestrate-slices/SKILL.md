# 슬라이스 오케스트레이션 스킬

스펙 문서(`docs/specs/NNN-*.md`)의 "구현 슬라이스(멀티 에이전트 감독용 경계)" 표를 실행하는 감독자 워크플로. 002-core 구현에서 검증된 방식이다.

## 전제

- 대상 스펙에 슬라이스 표(산출물 / 소유 경로 / 수정 금지 경로 / 선행 조건 / 상태)와 성공 기준 번호 매핑이 있어야 한다. 없으면 먼저 `write-spec` 스킬로 스펙을 보완한다.
- 슬라이스 간 소유 경로가 비중첩이면 worktree 격리 없이 같은 트리에서 병렬 작업이 안전하다. 소유가 겹치면 순차로 바꾸거나 감독자가 스펙의 슬라이스 분할을 먼저 수정한다.

## 1. 실행 계획 수립

- 슬라이스 표의 선행 조건 열로 의존 그래프를 그려 웨이브를 나눈다. 예: S1 단독 → S2/S3/S4 병렬 → S5 마무리.
- 계약(타입·API)을 결정하는 슬라이스는 반드시 선행 웨이브에 둔다. 공유 파일(`package.json`, `tsconfig.json`)을 소유한 슬라이스도 선행이 안전하다.
- 난이도별 모델 편성 기준:
  - **fable**: 이후 슬라이스 전체의 계약을 결정하는 설계 슬라이스 (타입/스키마/도메인 모델)
  - **opus**: 불변식·역연산·동시성 등 논리 복잡도가 높은 슬라이스
  - **sonnet**: 선행 계약이 확정되어 명세가 명확하고 기계적인 슬라이스 (직렬화, 순수 수학)
  - **감독자 직접**: 배럴/글루 통합, 최종 검증, 문서 상태 갱신 (마지막 슬라이스는 에이전트를 띄우지 않는 편이 빠르다)

## 2. 계약 전달

- 선행 슬라이스 에이전트에게 **"export된 public API 전체를 코드 블록으로 보고하라"**를 보고 형식에 필수로 넣는다.
- 후속 에이전트 프롬프트에는 감독자가 상상한 API가 아니라 **선행 에이전트가 보고한 실제 API**를 계약으로 붙여넣는다. 선행 완료 전에 후속을 띄우지 않는다.
- 계약이 코드 파일로 존재하므로 후속 에이전트에게 "시작 전에 해당 파일을 직접 읽어라"도 함께 지시한다(보고 요약과 실제 코드의 이중 확인).

## 3. 에이전트 프롬프트 필수 요소

각 슬라이스 에이전트 프롬프트에 반드시 포함한다:

1. 작업 디렉터리 절대 경로 + OS/셸 (Windows 11, PowerShell)
2. 시작 전에 읽을 파일: 해당 스펙, 상위 스펙(000), 선행 슬라이스 소스
3. **소유(생성/수정 가능) 파일 목록과 "이 목록 밖은 절대 수정 금지"** — 금지 대상을 구체적으로 나열(`index.ts`, 루트 설정, `lefthook.yml`, 다른 폴더)
4. 선행 계약(API 코드 블록) + 요구사항(스펙 §번호 인용) + 커버해야 할 성공 기준 번호
5. 병렬 동료 고지: "다른 에이전트가 <파일들>을 병렬 작업 중이다. `npx tsc --noEmit`에서 그 파일들의 일시적 에러는 무시하고 보고에만 적어라. 네 소유 파일의 에러만 책임진다"
6. 프로젝트 제약: 경계 린트 존재(허용 import), 주석 한국어 최소, oxfmt printWidth 100
7. 금지: git 상태 변경(commit/stage/branch), `--no-verify`, `LEFTHOOK=0`
8. 종료 전 검증 명령(아래 규칙)과 exit code 보고 의무
9. 보고 형식: 생성/수정 파일 목록 / export API 코드 블록 / 설계 결정과 근거 / 검증 exit code(소유 밖 에러 구분) / 소유 밖에서 발견한 문제

## 4. 병렬 실행 규칙

- 병렬 에이전트는 한 메시지에서 동시에 띄운다.
- **repo 전체를 대상으로 하는 쓰기 명령(`npx oxfmt` 인자 없이)은 에이전트에게 금지** — 파일 경합이 난다. 각자 소유 파일만 포맷: `npx oxfmt <소유 파일들>`.
- 테스트도 소유 파일 타깃으로: `npx vitest run <소유 테스트>`. 전체 `npm test`/`npx oxfmt --check`는 감독자가 마지막에 1회 실행한다.
- 에이전트 완료 통지를 기다리는 동안 감독자는 문서 상태 갱신(슬라이스 상태 "진행 중") 등 에이전트 소유 밖 작업만 한다. 에이전트 소유 파일은 건드리지 않는다.

## 5. 감독자 마무리 의무

전 슬라이스 완료 후 순서대로:

1. 마지막 통합 슬라이스(배럴 export 등)를 직접 수행한다. placeholder 정리(예: 임시 상수 → 실제 모듈 재export 교체)도 여기서 한다
2. 에이전트가 남긴 잔여물 정리: 소유 밖이라 못 고친 경고, 병렬 중 밀린 포맷. 정리 후 반드시 재검증한다
3. **전체 검증 1회**: `npm test` → `npx tsc --noEmit` → `npx oxlint` → `npx oxfmt --check` (전부 exit 0). 스펙 §5에 수동 확인 절차가 있으면 그것도 수행한다
4. 스펙의 성공 기준 표와 결과를 1:1 대조한다. 미충족 기준이 있으면 완료 선언 금지
5. 스펙 슬라이스 상태를 전부 "완료"로, `docs/specs/README.md` 인덱스를 "구현 완료"로 갱신하고 `npx oxfmt docs`로 표 정렬을 맞춘다
6. 최종 보고: 슬라이스×모델×결과 표, 검증 결과, 설계 결정 요약, 에이전트 토큰 사용량. **커밋은 사용자에게 제안만 하고 임의로 하지 않는다**

## 6. 실패·예외 처리

- 검증 실패 상태의 슬라이스를 완료 처리하지 않는다. 같은 에이전트에 이어서 메시지를 보내(컨텍스트 유지) 수정시키거나, 감독자가 원인을 파악해 재지시한다.
- 에이전트가 "소유 밖 파일 수정이 필요하다"고 보고하면 그 수정은 감독자가 직접 하거나 해당 파일 소유 슬라이스에 위임한다. 에이전트가 임의로 넘게 두지 않는다.
- 선행 슬라이스의 계약 변경이 필요해지면(후속에서 발견) 병렬 작업을 멈추고 계약 변경 → 영향 슬라이스 재지시 순서로 처리한다.
